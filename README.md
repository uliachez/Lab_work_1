## Задача 1. Параллельный поиск точек множества Мандельброта

### 1. Постановка задачи

Необходимо написать параллельную программу на языке C, которая находит заданное количество точек множества Мандельброта.

Программа принимает два аргумента командной строки:

```bash
./program nthreads npoints
```

где:

- `nthreads` — количество потоков;
- `npoints` — количество точек.

Результаты сохраняются в CSV-файл `points.csv`, содержащий координаты найденных точек.

### 2. Описание алгоритма

Множество Мандельброта определяется последовательностью:

$$
z_{n+1}=z_n^2+c,\quad z_0=0
$$

где z и c — комплексные числа.

Представим их в виде:

$$
z=x+yi,\quad c=a+bi
$$

Тогда итерационные формулы для действительной и мнимой частей имеют вид:

$$
x_{n+1}=x_n^2-y_n^2+a
$$

$$
y_{n+1}=2x_ny_n+b
$$

Если в процессе вычислений выполняется условие:

$$
x^2+y^2>4
$$

то последовательность выходит за пределы круга радиуса 2 и точка не принадлежит множеству.

В программе проверка ограничена 1000 итерациями. Если за это время последовательность не выходит за границу, точка считается подходящей.

Таким образом, используется приближённая проверка принадлежности множеству Мандельброта.

Координаты кандидатов генерируются случайным образом в диапазонах:

$$
a\in[-2;1],\quad b\in[-1.5;1.5]
$$

Программа продолжает генерацию до тех пор, пока не будет найдено заданное количество точек.

### 3. Реализация программы

Программа написана на языке C с использованием библиотеки Pthreads.

Для хранения координат используется структура `Point`, состоящая из двух полей `a` и `b`.

Структура `ThreadArgs` содержит номер потока, начальный индекс участка массива, количество точек, которые необходимо найти, и указатель на общий массив результатов.

**Функция `is_mandelbrot()`** выполняет проверку одной точки. На каждой итерации вычисляются новые значения действительной и мнимой частей комплексного числа. Если квадрат модуля превышает 4, функция возвращает `0`. Если точка прошла 1000 итераций, функция возвращает `1`.

**Функция `thread_work()`** выполняется каждым рабочим потоком. Она генерирует координаты с помощью `rand_r()`, проверяет их функцией `is_mandelbrot()` и сохраняет подходящие точки в массив.

У каждого потока собственная переменная `seed`, поэтому состояния генераторов случайных чисел не являются общими.

**Функция `parse_positive()`** проверяет корректность аргументов командной строки с помощью `strtol()`. Она отклоняет некорректные значения и неположительные числа.

В функции `main()` проверяются аргументы и размеры выделяемой памяти. Затем создаются рабочие потоки, выполняются вычисления, измеряется время и записывается результат в CSV.

Программа также обрабатывает ошибки выделения памяти, создания и ожидания потоков, получения времени и записи файла.

### 4. Организация параллельных вычислений

Количество точек распределяется между потоками примерно поровну.

Сначала вычисляется основное количество точек на один поток:

$$
base=\left\lfloor\frac{npoints}{nthreads}\right\rfloor
$$

Остаток вычисляется как:

$$
remainder=npoints\bmod nthreads
$$

Если количество точек не делится на число потоков без остатка, дополнительные точки назначаются первым потокам.

Например, при 10 точках и 3 потоках распределение будет следующим:

| Поток | Количество точек |
|---|---:|
| 0 | 4 |
| 1 | 3 |
| 2 | 3 |

Для создания потоков используется `pthread_create()`, а для ожидания их завершения — `pthread_join()`.

Каждый поток записывает результаты в свой участок общего массива. Участки не пересекаются, поэтому для записи координат не требуется мьютекс.

После завершения всех потоков основной поток записывает массив в файл `points.csv`.

Если запрошенное количество потоков превышает количество точек, программа ограничивает число потоков количеством точек.

## Задача 2. Моделирование задачи N тел с использованием Pthreads

### 1. Постановка задачи

Необходимо написать параллельную программу на языке C, которая моделирует движение (N) материальных точек в трёхмерном пространстве под действием силы всемирного тяготения.

Для каждой точки заданы масса, начальные координаты и компоненты начальной скорости.

Программа принимает три аргумента командной строки:

```bash
./nbody tend input_file num_threads
```

где:

- `tend` — конечное время моделирования;
- `input_file` — имя входного файла с параметрами материальных точек;
- `num_threads` — количество рабочих потоков.

Первая строка входного файла содержит количество материальных точек (N). Каждая из следующих (N) строк содержит семь чисел: массу, три начальные координаты и три компоненты начальной скорости.

Результаты моделирования сохраняются в файл `trajectory.csv`. Каждая строка соответствует определённому моменту времени и содержит время и координаты всех материальных точек.

### 2. Описание алгоритма

#### 2.1. Расчёт гравитационных сил

Для моделирования движения материальных точек используется закон всемирного тяготения.

Сила, действующая на тело (i) со стороны тела (j), определяется формулой:

$$
\vec F_{ij} =
G\frac{m_i m_j}{|\vec r_j-\vec r_i|^3}
(\vec r_j-\vec r_i),
$$

где:

- $$G=6.67430\cdot10^{-11}$$ — гравитационная постоянная;
- $$m_i$$, $$m_j$$ — массы тел;
- $$\vec r_i$$, $$\vec r_j$$ — радиус-векторы тел.

В трёхмерном пространстве расстояние между телами определяется следующим образом:

$$
r^2=(x_j-x_i)^2+(y_j-y_i)^2+(z_j-z_i)^2.
$$

В программе вычисляется коэффициент силы:

$$
factor=\frac{Gm_i m_j}{r^2\sqrt{r^2}}.
$$

После этого рассчитываются компоненты силы:

$$
F_x=factor(x_j-x_i),
$$

$$
F_y=factor(y_j-y_i),
$$

$$
F_z=factor(z_j-z_i).
$$

Общая сила, действующая на каждое тело, представляет собой сумму сил со стороны остальных тел:

$$
\vec F_i=\sum_{j\ne i}\vec F_{ij}.
$$

При вычислении используется третий закон Ньютона:

$$
\vec F_{ij}=-\vec F_{ji}.
$$

Поэтому для каждой пары тел сила рассчитывается только один раз. Полученная сила прибавляется к силе первого тела и вычитается из силы второго тела. Это позволяет сократить количество вычислений по сравнению с независимым расчётом силы для каждого тела.

Если квадрат расстояния между телами меньше $10^{-20}$, взаимодействие этой пары пропускается во избежание деления на слишком малое значение.

#### 2.2. Интегрирование уравнений движения

Движение каждого тела описывается вторым законом Ньютона:

$$
m_i\frac{d^2\vec r_i}{dt^2}=\vec F_i.
$$

Переходя к системе уравнений первого порядка, получаем:

$$
\frac{d\vec r_i}{dt}=\vec v_i,
$$

$$
\frac{d\vec v_i}{dt}=\frac{\vec F_i}{m_i}.
$$

Для численного решения используется явный метод Эйлера первого порядка. В программе задан постоянный шаг времени:

$$
\Delta t=0.01.
$$

На каждом шаге сначала обновляются координаты с использованием текущей скорости:

$$
\vec r_i^{,n+1}=\vec r_i^{,n}+\vec v_i^{,n}h,
$$

затем обновляется скорость:

$$
\vec v_i^{,n+1}=\vec v_i^{,n}
+\frac{\vec F_i^{,n}}{m_i}h,
$$

где (h) — текущий шаг интегрирования.

Таким образом, алгоритм состоит из последовательных этапов:

1. Запись текущего времени и координат всех тел в CSV-файл.
2. Обнуление локальных массивов сил.
3. Распределение парных взаимодействий между потоками.
4. Параллельное вычисление гравитационных сил.
5. Суммирование локальных результатов.
6. Обновление координат и скоростей тел.
7. Увеличение времени моделирования на величину шага.
8. Вычисления повторяются до достижения конечного времени.

### 3. Реализация программы

Программа написана на языке `C` с использованием библиотеки `Pthreads` для организации многопоточных вычислений.

Для хранения данных используются следующие структуры и массивы.

Структура **Body** содержит параметры одной материальной точки:

- `m` — масса;
- `r[3]` — координаты;
- `v[3]` — компоненты скорости.

Структура **ThreadData** содержит параметры рабочего потока:

- `id` — идентификатор потока;
- `start`, end — границы диапазона индексов тел, обрабатываемых потоком;
- `n` — общее количество тел;
- `step` — номер шага моделирования;
- `bodies` — указатель на общий массив тел;
- `forces` — указатель на локальный массив сил потока.

#### Основные функции программы:

`calculate_forces()` выполняет вычисление гравитационных сил. Поток перебирает назначенные ему тела и рассматривает пары взаимодействий с индексами (i<j). Для каждой пары рассчитываются три компоненты силы, которые записываются в локальный массив сил потока.

`main()` выполняет основные операции программы: обработку аргументов командной строки, чтение входных данных, выделение памяти, создание потоков, организацию цикла моделирования и запись результатов в CSV-файл.

### 4. Организация параллельных вычислений

Параллельная часть программы отвечает за вычисление гравитационных сил между материальными точками.

Общее количество тел распределяется между потоками примерно поровну. Для потока с номером (k) границы диапазона вычисляются по формулам:

$$
start_k=\left\lfloor\frac{Nk}{P}\right\rfloor,
$$

$$
end_k=\left\lfloor\frac{N(k+1)}{P}\right\rfloor,
$$

где (N) — количество тел, (P) — количество потоков.

Поток обрабатывает индексы от start включительно до end не включительно. Такое распределение позволяет охватить все индексы без пересечений между назначенными диапазонами.

#### Локальные массивы сил

Каждый поток использует отдельный массив `local_forces`, в котором накапливаются силы для всех тел. Это необходимо, поскольку одна и та же пара тел может влиять на тела, принадлежащие разным диапазонам потоков.

Использование отдельных массивов предотвращает одновременную запись нескольких потоков в одни и те же элементы памяти и позволяет обойтись без мьютекса при вычислении сил.

После завершения вычислений вызывается `pthread_join()` для каждого созданного потока. Затем главный поток суммирует локальные массивы:

$$
F_i=\sum_{k=0}^{P-1}F_i^{(k)},
$$

где $F_i^{(k)}$ — вклад потока (k) в силу, действующую на тело (i).

Полученные силы используются для обновления координат и скоростей.

Создание потоков осуществляется с помощью `pthread_create()`, а ожидание завершения — с помощью `pthread_join()`.

Вычислительная сложность расчёта сил на одном шаге составляет $O({N^2})$, поскольку необходимо обработать все пары тел. При увеличении количества тел объём вычислений существенно возрастает, поэтому параллелизация позволяет сократить время выполнения программы.

## Задача 2. Блокировки чтения-записи

### 1. Постановка задачи
Необходимо реализовать собственную блокировку чтения-записи (RWLock) с использованием библиотеки POSIX Threads, проверить её работу на многопоточном односвязном списке и сравнить производительность с библиотечной реализацией pthread_rwlock_t.
#### Инструкция по запуску
Перейти в папку проекта через терминал Ubuntu (WSL)

Выполнить следующие команды:

```bash
make clean
make all
make benchmark | tee benchmark_output.txt
```

После выполнения результаты измерений сохраняются в `results.csv`, а итоговый вывод программы — в `benchmark_output.txt`.
### 2. Реализация алгоритма

В работе реализована собственная блокировка RWLock, которая позволяет нескольким потокам одновременно читать общие данные, но предоставляет исключительный доступ потоку, выполняющему запись.

Для реализации используется структура my_rwlock_t, содержащая:

**mutex** — мьютекс для защиты внутреннего состояния блокировки;

**readers_cv и writers_cv** — условные переменные для ожидания читателей и писателей;

**active_readers** — количество активных читателей;

**waiting_readers** — количество ожидающих читателей;

**waiting_writers** — количество ожидающих писателей;

**writer_active** — флаг активного писателя.

Реализованы следующие функции:

**my_rwlock_init()** — инициализирует мьютекс, обе условные переменные и устанавливает начальные значения счётчиков и флага в ноль.

**my_rwlock_rdlock()** — предоставляет потоку доступ на чтение. Если сейчас работает писатель или есть ожидающие писатели, поток ожидает на условной переменной readers_cv. В противном случае увеличивается счётчик активных читателей.

**my_rwlock_wrlock()** — предоставляет исключительный доступ на запись. Если есть активные читатели или другой писатель, поток ожидает на условной переменной writers_cv. После получения разрешения устанавливается флаг writer_active.

**my_rwlock_unlock()** — освобождает ранее полученную блокировку. При завершении чтения уменьшается счётчик active_readers, при завершении записи сбрасывается writer_active. Когда активных владельцев не остаётся, функция пробуждает ожидающие потоки.

**my_rwlock_destroy()** — проверяет состояние блокировки и уничтожает мьютекс и условные переменные после завершения работы с RWLock.

В реализации выбрана политика приоритета писателей. Если хотя бы один писатель ожидает получения блокировки, новые читатели не допускаются. Это предотвращает постоянное откладывание записи из-за непрерывного поступления новых читателей. Недостатком такого подхода является возможность длительного ожидания читателей при большом количестве писателей.

Для ожидания используется pthread_cond_wait(), которая освобождает внутренний мьютекс на время ожидания и повторно захватывает его перед возвращением. Условия допуска проверяются в цикле while, поскольку пробуждение не гарантирует, что блокировка уже доступна.

### 3. Логика работы программы и основных функций

**3.1. Инициализация — my_rwlock_init()**

- Проверяет, что указатель на блокировку не равен NULL.
- Инициализирует мьютекс и две условные переменные.
- Устанавливает все счётчики и флаг писателя в 0.
- При ошибке освобождает ранее созданные ресурсы.

**3.2. Блокировка чтения — my_rwlock_rdlock()**

- Захватывает внутренний мьютекс.
- Увеличивает количество ожидающих читателей.
- Проверяет, нет ли активного писателя или ожидающих писателей.
  - Если есть:
    - Поток ожидает на readers_cv, временно освобождая мьютекс.
    - После пробуждения снова захватывает мьютекс и проверяет условие.
- Когда чтение разрешено:
  - Уменьшает количество ожидающих читателей.
  - Увеличивает количество активных читателей.
- Освобождает внутренний мьютекс.

**3.3. Блокировка записи — my_rwlock_wrlock()**

- Захватывает внутренний мьютекс.
- Увеличивает количество ожидающих писателей.
- Проверяет, нет ли активного писателя или активных читателей.
  - Если есть:
    - Поток ожидает на writers_cv, временно освобождая мьютекс.
    - После пробуждения снова захватывает мьютекс и повторно проверяет условие.
- Когда запись разрешена:
  - Уменьшает количество ожидающих писателей.
  - Устанавливает writer_active = 1.
- Освобождает внутренний мьютекс.

**3.4. Освобождение блокировки — my_rwlock_unlock()**

- Захватывает внутренний мьютекс.
- Определяет, какая блокировка освобождается:
  - Если активен писатель — устанавливает writer_active = 0.
  - Иначе, если есть активные читатели — уменьшает active_readers на один.
  - Если блокировка не занята — возвращает ошибку EPERM.
- Если активных читателей и писателей больше нет:
  - При наличии ожидающих писателей пробуждает одного через pthread_cond_signal().
  - Иначе пробуждает всех ожидающих читателей через pthread_cond_broadcast().
- Освобождает внутренний мьютекс.

**3.5. Уничтожение — my_rwlock_destroy()**

- Проверяет, что блокировка не используется потоками.
- Если есть активные или ожидающие потоки — возвращает EBUSY.
- Иначе уничтожает условные переменные и мьютекс.
